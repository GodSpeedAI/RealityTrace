Asymmetric Diagnostic Friction & 9-Locus Attribution Simulator

Autonomous coding agents suffer from a catastrophic pathology: when a test fails due to a network blip or flaky test runner, they assume the high-level architecture is wrong and hallucinate model refactorings. SXR prevents this by formalizing verification disagreements as unassigned Residuals ($R = G_{declared} \setminus G_{observed}$), enumerating 9 mutually exclusive failure loci, and mathematically forbidding model-level modifications until cheaper infrastructure loci have been evidence-excluded.

AC-DIAG-001 Asymmetric Friction Guard

Enforced in sxr-cli/src/commands.rs:diagnostic_propose. The function inspects all registered candidate hypotheses. If the target locus is declared_model, it verifies that every locus in Tiers 1–3 has at least one recorded evidence envelope where direction == Direction::Contradicts. If any cheaper locus remains unadjudicated, the command exits with code 3.

§12.5a The 4 Settlement Conditions

Enforced in sxr-cli/src/commands.rs:diagnostic_settle. Rather than picking the "most likely" candidate probabilistically, SXR requires mathematical exclusion: the winner must have positive supporting evidence, and all competing alternatives must have verified contradictory proof.

Source: sxr-cli/src/commands.rs:580
